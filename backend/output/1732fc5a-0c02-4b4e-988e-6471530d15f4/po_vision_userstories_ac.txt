### 1) EPIC Vision Statement
> **Vision:**  
> Enable customers and internal users to securely and seamlessly access the bank’s online platform through a modern, reliable, and user-friendly login experience that protects account credentials, supports password recovery, remembers trusted devices, and defends against unauthorized access through lockout and audit mechanisms.

---

### 2) INVEST-Compliant User Stories

#### Story 1: Secure Login
**As a** banking customer  
**I want** to log in securely using my username and password  
**So that** I can access my online banking account and manage my financial activities safely.

#### Story 2: Password Recovery
**As a** banking customer  
**I want** to reset my password if I forget it  
**So that** I can regain access to my account without contacting customer support.

#### Story 3: Remember Me Option
**As a** frequent user  
**I want** the login page to remember my username on this trusted device  
**So that** I can log in faster without re-entering my credentials each time.

#### Story 4: Account Lockout
**As a** security administrator  
**I want** accounts to be temporarily locked after multiple failed login attempts  
**So that** we can prevent brute-force attacks and protect customer accounts.

Each story is **Independent**, **Negotiable**, **Valuable**, **Estimable**, **Small**, and **Testable**.

---

### 3) Detailed Acceptance Criteria (GIVEN/WHEN/THEN)

#### Story 1 – Secure Login
**GIVEN** a user with a valid username and password  
**WHEN** they enter their credentials and click “Login”  
**THEN** the system authenticates their identity, establishes a session, and navigates to the account dashboard.  

**GIVEN** invalid credentials  
**WHEN** they attempt to log in  
**THEN** the system displays an error message “Invalid username or password” and does not create a session.

---

#### Story 2 – Password Recovery
**GIVEN** a user who cannot remember their password  
**WHEN** they click “Forgot password” and provide their registered email or username  
**THEN** the system sends a secure password reset link with a time-limited token to their email.  

**GIVEN** the user accesses the password reset link within its validity period  
**WHEN** they set a new password meeting defined complexity rules  
**THEN** the system updates their credentials and confirms successful reset.  

**GIVEN** the token has expired or been used  
**WHEN** the user attempts to use it  
**THEN** the system displays “Reset link expired” and prompts them to request a new one.

---

#### Story 3 – Remember Me Option
**GIVEN** a user selects “Remember my username” during login  
**WHEN** they return to the login page from the same device/browser  
**THEN** their username field is pre-filled while the password field remains empty.  

**GIVEN** privacy requirements  
**WHEN** the user logs in from a public or incognito session  
**THEN** the system does not persist the username or create any stored cookies marked as “Remember Me”.

---

#### Story 4 – Account Lockout
**GIVEN** a user account with repeated failed login attempts (e.g., 5 consecutive failures)  
**WHEN** the threshold is reached  
**THEN** the account is locked for a defined time (e.g., 15 minutes) and audit-logged.  

**GIVEN** a locked account  
**WHEN** the user attempts to log in again within the lockout period  
**THEN** the system displays “Account temporarily locked—please try again later” and denies authentication.  

**GIVEN** the lockout period expires  
**WHEN** the user enters correct credentials  
**THEN** the system restores access and resets the failed-attempt counter.
