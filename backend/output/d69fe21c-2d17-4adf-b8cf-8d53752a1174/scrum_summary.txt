### **Executive Summary – Customer Profile Data Migration (PostgreSQL → MongoDB)**  

#### **Scope**
- Migrate ~2M customer profiles (~150 GB) from PostgreSQL to MongoDB to support **flexible, country-specific schemas** for global expansion.  
- Maintain **API compatibility**, **zero downtime**, and **zero data loss**.  
- Use **CDC‑based backfill**, **dual‑write (2 weeks)** via feature flags, and a **validated rollback path (<1 hour)**.  
- Performance target: **p95 < 50 ms read latency** under load.  
- Completion expected within **3‑week sprint** (planning + execution).  

#### **Current Readiness**
- **Schema Design:** Document model finalized; indexes defined (customer_id, country_code, email).  
- **CDC Pipeline:** Connector selected and verified for incremental sync.  
- **Infrastructure:** AWS MongoDB Atlas 3‑node replica set provisioned; replication and failover tested.  
- **Feature Flags:** Dual‑write and rollback toggles implemented in API layer.  
- **Validation Tools:** Parity‑check scripts completed; automated hash comparison ready for 100% verification.  
- **QA Automation:** Regression, performance, and rollback tests scripted and ready to execute.  

#### **Key Risks & Mitigations**
| Risk | Impact | Mitigation |
|------|---------|------------|
| **Data loss or inconsistency during CDC/backfill** | High | Continuous CDC until parity confirmed; checksum validation and audit logs. |
| **MongoDB latency exceeds 50 ms p95** | High | Pre‑built indexes; tuned connection pooling; early load testing. |
| **Dual‑write synchronization lag** | High | Durable write acknowledgments; monitoring parity dashboard. |
| **Rollback path issues** | Medium | Staging rehearsal; automated switch verified. |
| **Regulatory data handling (GDPR, Japan PII)** | High | Field‑level encryption; IAM least‑privilege; compliance checklist. |
