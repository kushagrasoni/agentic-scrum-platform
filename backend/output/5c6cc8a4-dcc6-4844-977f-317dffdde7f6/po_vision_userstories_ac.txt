### **1. Vision Statement**

Enable customers to securely and seamlessly access their online banking accounts through a modern web login experience that adheres to regulatory security standards, minimizes friction, and safeguards against unauthorized access — forming the foundation for all digital banking interactions.

---

### **2. INVEST-Compliant User Stories**

**User Story 1: Login with Username and Password**
> As a banking customer,  
> I want to log in using my registered username and password,  
> so that I can securely access my online account and manage my finances.

**User Story 2: Forgot Password Flow**
> As a banking customer,  
> I want an option to reset my password if I forget it,  
> so that I can regain access to my account without contacting support.

**User Story 3: Remember Me Functionality**
> As a returning customer on a trusted personal device,  
> I want the system to remember me,  
> so that I don’t have to re-enter credentials each time while maintaining security compliance.

**User Story 4: Account Lockout on Failed Attempts**
> As a banking customer,  
> I want my account to be temporarily locked after multiple unsuccessful login attempts,  
> so that my account remains protected against brute-force attacks.

---

### **3. Acceptance Criteria (GIVEN / WHEN / THEN)**

#### **User Story 1 – Login with Username and Password**
- **GIVEN** a registered user on the login page  
  **WHEN** they enter a valid username and password  
  **THEN** the system authenticates and redirects them to their account dashboard.  

- **GIVEN** an invalid username or password  
  **WHEN** the user attempts to log in  
  **THEN** the system displays an error message and does not grant access.  

- **GIVEN** the login service is connected to backend authentication APIs  
  **WHEN** authentication succeeds  
  **THEN** an audit entry is logged (user ID, timestamp, IP) and a secure session token is issued.

---

#### **User Story 2 – Forgot Password Flow**
- **GIVEN** a user has forgotten their password  
  **WHEN** they click “Forgot Password”  
  **THEN** they are prompted to enter their registered email/username.  

- **GIVEN** the email/username matches a valid account  
  **WHEN** the user submits the form  
  **THEN** the system sends a password reset link valid for 15 minutes.  

- **GIVEN** a user opens the reset link within validity  
  **WHEN** they set a new password meeting complexity rules  
  **THEN** the password is updated, audit logged, and the user can log in with the new password.

---

#### **User Story 3 – Remember Me Functionality**
- **GIVEN** a user is logging in from a trusted personal device  
  **WHEN** they check “Remember Me” and successfully log in  
  **THEN** the system stores a secure device token so they are remembered on subsequent visits for up to 30 days.  

- **GIVEN** the device token expires or is manually revoked  
  **WHEN** the user revisits the site  
  **THEN** the system requires fresh login credentials.

---

#### **User Story 4 – Account Lockout after Failed Attempts**
- **GIVEN** a user enters incorrect credentials  
  **WHEN** they fail five times consecutively  
  **THEN** the system locks the account for 15 minutes and displays a “Your account has been temporarily locked” message.  

- **GIVEN** the lockout period has expired  
  **WHEN** the user next attempts to log in with correct credentials  
  **THEN** the system unlocks the account and grants access.

- **GIVEN** an account lockout event occurs  
  **WHEN** it is triggered  
  **THEN** an audit record is written capturing timestamp, IP, and account ID for monitoring.

---

**Summary:**  
This EPIC delivers a secure, compliant banking login experience supporting username/password authentication, password recovery, session persistence, and brute-force protection — establishing a core capability for all digital banking operations.
